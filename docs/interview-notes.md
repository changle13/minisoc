# MiniSOC 面试笔记

## 1. 为什么不用 ELK / Wazuh？

答：

- 笔记本资源有限，ELK 会占大量内存和磁盘
- 项目重点是检测、关联和响应闭环，不是搜索集群工程
- 用 PostgreSQL 的 JSONB 保留原始日志，项目规模足够
- 扩展路径清晰：事件量上来后可以换 ClickHouse/OpenSearch，接入层和检测层不需要重写

面试表达：

> 我是刻意选择 PostgreSQL 做 MVP，把复杂度留给检测和响应；同时文档里写清了向 ClickHouse/OpenSearch 扩展的路径。

## 2. 一天 100 万条日志怎么扩展？

答：

- Agent 批量上报，API 只做校验和入队
- 用 Redis Streams/Kafka 解耦接入与检测
- 检测 Worker 水平扩展
- 事件存储按时间分区，设置保留策略
- 搜索型查询迁移到 ClickHouse/OpenSearch
- 告警和工单仍保留在 PostgreSQL

## 3. Event、Alert、Incident 的区别？

答：

- Event：原始证据，不可变，保留 `raw`
- Alert：规则命中结果，可去重、更新次数
- Incident：多条相关 Alert 组成的案件，给人处理

一句话：

> Event 负责取证，Alert 负责发现，Incident 负责处理。

## 4. 告警怎么去重？

答：

- 去重键：`rule_id + entity + 时间桶`
- 同一窗口内重复触发只更新 `count`、`last_seen`
- 例如 SSH 爆破：`ssh_bruteforce:192.168.65.1:2026-11-03T05:55`

好处：

- 避免 100 次失败生成 100 条告警
- 保留攻击次数和时间范围
- 降低告警疲劳

## 5. 如何降低误报？

答：

- 阈值：5 分钟内失败 ≥ 5 次
- 时间窗口和实体聚合
- 白名单和规则调参
- 关联多条告警形成 Incident
- 用真实攻击和正常流量做基线
- 后续引入规则测试集和误报统计

注意：目前还没有完整误报率数据，简历上不能编。

## 6. 响应 Agent 怎么防止被滥用？

答：

- HMAC-SHA256 签名，secret 不放在请求里
- 时间戳 60 秒窗口，防重放
- IP 白名单，禁止封 SOC、Victim、localhost
- 只接受 `/block` 和 `/unblock` 两个动作
- 独立 iptables 链，方便清理
- 默认 dry-run
- 本地审计 + SOC `response_actions` 双份记录

生产环境还要加：

- mTLS
- 网络 ACL，只允许 SOC 访问 9000
- 专用低权限服务账号
- 限流和人工审批

## 7. API Key 和 JWT 有什么区别？

答：

- API Key：给 Agent/机器用，长期、共享、无用户身份
- JWT：给人/前端用，登录后签发，带用户 ID、角色、过期时间

所以：

- 日志接入用 API Key
- 告警、事件、响应查询用 JWT + RBAC

## 8. 为什么检测和响应是同步的？

答：

- MVP 先保证链路简单可验证
- 同步实现容易调试和演示

生产问题：

- 检测失败会导致接入失败
- 响应 Agent 慢会拖慢接入
- 不适合高吞吐

改进：

- 接入只写事件和入队
- 检测 Worker 异步消费
- 响应动作异步执行并记录状态

## 9. 项目最大的难点是什么？

可选回答：

- 把“日志 → 事件 → 告警 → 案件 → 响应”建模清楚，而不是写成一张大表
- 响应 Agent 的安全边界：既要有用，又不能变成远程 root 执行入口
- 保证 Agent 重启不丢日志、不重复发送，offset 只在发送成功后推进
- 在同步实现下保证告警和响应失败互不回滚

## 10. 项目有什么局限？

答：

- 单机、无高可用
- 检测和响应同步
- 未接 Alembic
- 开发默认密码和 JWT secret
- 只覆盖 SSH 爆破
- 前端 localStorage 存 JWT
- 未做 HTTPS、限流和完整自动化测试

面试时要主动说局限，再讲改进路径，比假装完美更可信。

## 11. 为什么自研 Agent，不用 Filebeat？

答：

- 项目目标是理解 offset、批量、重试和日志解析
- 自研 Agent 可以讲清楚“至少一次”语义
- 生产环境可以换成 Filebeat/Vector，项目里的数据模型和检测逻辑不变

## 12. 这个项目和“装 Wazuh 截图”有什么区别？

答：

- 我实现了事件接入、规则检测、告警去重、事件关联、响应审计
- 有真实 SSH 爆破验证
- 能讲清楚每一层的数据模型和失败模式
- 不是只部署一个产品，而是理解并实现检测闭环
